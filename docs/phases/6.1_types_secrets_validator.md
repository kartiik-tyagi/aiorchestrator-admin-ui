## In scope

### Types (`src/api/types.js`)

- `TOOL_VERBS` fallback includes `api`
- Fallbacks: `API_AUTH_TYPES`, `API_SUCCESS_MODES`, `API_KINDS`, `LISTEN_INPUT_TYPES`, `DATE_ORDER`, `API_TOOL_RESULT_OPTIONS`, `SESSION_TEMPLATE_KEYS`
- MetaCatalog JSDoc: `api_tool_result_options`, `api_success_modes`, `api_auth_types`, `listen_input_types`, `date_order`
- Slot typedef: `input_type`, `length_rule: { op, n }`
- Tool node: `api_id`

### Client (`src/api/client.js`)

| Method | Path |
|---|---|
| `listProfileApiSecrets(id)` | `GET /v1/profiles/{id}/api-secrets` |
| `getProfileApiSecret(id, apiId)` | `GET …/api-secrets/{api_id}` |
| `putProfileApiSecret(id, apiId, auth_payload)` | `PUT` body `{ auth_payload }` |
| `deleteProfileApiSecret(id, apiId)` | `DELETE` |

Optional prep (used by 6.4): `publishFlow` / `validateFlow` accept optional `{ profile_id, profile_version }` query.

### Validators

- `flowValidate.js`: **remove** warning that `tool_result` is unused
- Add: Tool `api` needs `api_id`; three distinct `tool_result` options success|fail|error
- Add: Speak/prompt text scan — unknown `{{session.*}}` → error; allowlisted session keys only
- `profileValidate.js`: duplicate `api_integrations[].id`; non-https URL unless `allow_insecure_http`; write without success_requires (unless http_only + 204-only http_ok)
