## Operator outcome

I can turn barge off on welcome, opt a hub into globals, and build a Decide — without leaving the canvas.

## Goal

The inspector and flow-level panel edit every industrial field already on `coral-telecom-inbound`, and publish uses **server** validate as well as the client preview.

---

## In scope

### Document-level (nothing selected)

- `globals`: multi-select of edges that are `kind=global` (must have intent or option). Show matcher labels.
- `conversation_policy` override — same groups as profile **plus inherit** on interruption modes (`inherit`|`off`|`on`|`after_ms`). Empty = inherit profile. Pointers/omitted keys stay omitted.
- Existing: entry, default locale, binding_refs, matrix.

### Per node (by type)

| Type | Extra fields |
|---|---|
| Speak / Inform | `interrupt` (catalog `interrupt_modes`), `interrupt_after_ms` (when `after_ms`), `mandatory_delivery` |
| ListenChoice / ListenLanguage / ListenSlot | `listen_policy` (`timeout_ms`, `retries`, `repair_edge_id`, `exhausted_edge_id`), `global_intents`, `allowed_intents`, existing repair |
| ListenSlot | typed `slot`: key, validator, enum[], pattern, confirm, redact, class |
| Decide | ordered `decide.rules` (slot + eq/in/exists → outgoing `edge_id`) + `else_edge_id` |
| Tool | existing verb + `matrix_intent` |

`allowed_intents`: chips from the **selected / pinned** profile’s `intent_catalog` (load latest or draft of a profile the operator picks in the flow panel — default: first answer-pin profile for this flow, else a profile dropdown). Empty allowed.

`global_intents`: chips from matchers of edges listed in `doc.globals`.

### APIs

- Keep whole-document `PUT /v1/flows/{id}/draft` (do **not** require granular `draft/nodes` this phase).
- `POST /v1/flows/{id}/validate` before publish; show server issues.
- Version inspect: `GET /v1/flows/{id}/versions` + `GET …/versions/{ver}` read-only.

### Client validate

Extend 1.3 with conversation_policy range checks (ms ≥ 0, `safe_retry_max` 0–3, interrupt enum including inherit).

## Out of scope

- Granular REST for each node/edge.
- Changing auto-layout algorithm.
- Supervisor.

## Backend contract (read-only)

- Node/doc fields: `internal/flow/doc.go`, `policy.go`
- Catalog: `interrupt_modes`, `flow_interrupt_modes` already on `GET /v1/meta/catalog`
- Live inbound extras: `mandatory_delivery`, `interrupt`, `listen_policy`, `global_intents`, `globals[]` (8 ids)
- `allowed_intents` identity vs profile catalog is checked at **session pin**, not flow-alone publish — UI still should not offer unknown ids

## Current baseline

- Inspector: id, type, tool, matrix_intent, binding_ref, prompt, repair max_retries / unclear prompt, edges, flow entry/locale/binding_refs/matrix.
- No interrupt / listen_policy / globals / Decide / slot editors.
- Client has `putFlowDraft` / `publishFlow` / `getFlowVersion`; missing `validateFlow` HTTP and version **list**.

## UX

- Inspector sections: Properties → Interrupt / Delivery → Listen policy → Intents (allowed + global) → Slot or Decide → Prompt → Repair.
- Hide sections that do not apply to the node type (do not show a wall of disabled fields).
- Globals at flow level: “Always available on opted-in listen steps” — not “unused edge kind”.
- Decide: add rule, reorder, pick outgoing edge from a dropdown of this node’s edges (create edges first — helper text).

## Do / Do-not

- **Do** open live inbound and show existing interrupt / listen_policy / global_intents values.
- **Do** publish after a no-op field touch (1.1 already killed `cx`).
- **Do not** write `cx`.
- **Do not** put global-scope intents into `allowed_intents`.

---

## Exit criteria

1. Live inbound nodes show interrupt / listen_policy / global_intents / mandatory_delivery as on the server.
2. Editing hub `global_intents` and publishing succeeds.
3. A new Decide with two rules + else publishes; a broken Decide is blocked locally and by server validate.
4. Client validate and server validate agree on the live inbound flow (no extra false errors).
5. Version list opens a published doc read-only.

## Risks

| Risk | Mitigation |
|---|---|
| Which profile supplies intent chips | Pin lookup + explicit dropdown |
| `listen_policy` vs `repair` overlap | Show both; do not delete `repair` when editing listen_policy |
| Decide needs edges first | Helper: “Draw outgoing edges, then name them in rules” |
