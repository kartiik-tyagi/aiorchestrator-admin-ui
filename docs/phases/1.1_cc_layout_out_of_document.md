# Phase 1.1 — CC: layout out of document (unblock publish)

**Wave:** CC safety  
**Depends:** 0.1  
**Unlocks:** 1.2, 1.3, and any later publish from this UI  
**Lock:** [PROGRAMME.md](./PROGRAMME.md)

---

## Operator outcome

I can open `coral-telecom-inbound`, move boxes, save, and publish. The call still works. I never see `opaque cx is rejected`.

---

## Goal

Stop writing canvas positions into `coral.flow.v1`. The kernel (CC.2) rejects any non-empty `cx`. Layout becomes a **browser-local** concern.

---

## In scope

- Remove `withLayout()` writing `doc.cx.layout` on save and publish.
- Persist positions in `localStorage` key `orch_cc_layout:<flowId>` as `{ [nodeId]: { x, y } }`.
- On load: if the draft still contains `cx.layout`, **read it once**, copy into localStorage, **strip `cx` from the in-memory document** before any PUT/POST.
- `resolveLayout(doc)` reads localStorage first, then leftover `cx` (migrate), then auto-layout.
- Relayout button only changes local positions (`cx: undefined` already used in one path — keep that idea).
- Delete every comment/README line that says “Go ignores `cx`” or “runtime never reads `cx`”.
- `docForWire()` returns the document **without** `cx` (and without other UI-only keys).
- Rename hygiene: when a node id changes, move the localStorage entry with it (builder already remaps `layout` state).

## Out of scope

- New node fields (2.2).
- Validator changes except a cheap “do not send `cx`” strip (full validator truth is 1.3).
- Shared layout across browsers (not possible without backend).

---

## Backend contract (read-only)

`internal/flow/policy.go` `validateCXRejected`: non-empty / non-null `cx` → `policy_validation_failed` field `cx`.  
`internal/flow/doc.go`: `CX json.RawMessage` is **legacy opaque policy**, not canvas.

Draft PUT and publish POST accept the same `coral.flow.v1` body. Layout is not a field.

---

## Current baseline (must change)

- `src/lib/layout.js` — `withLayout` writes `cx.layout`; comment is false.
- `src/pages/FlowBuilder.jsx` — `docForWire = () => withLayout(doc, layoutRef.current)` used by save and publish.
- `src/pages/builder/Inspector.jsx` — remaps `d.cx.layout` on rename.
- `README.md` — “persists positions into `doc.cx.layout`”.

---

## UX

- No new controls. Save / Publish buttons stay.
- If a loaded draft had `cx`, the first save after this phase writes a clean document; toast can stay “Draft saved”.
- A second browser on the same flow auto-lays out (acceptable). Copy: do not promise shared positions.

---

## Do / Do-not

- **Do** strip `cx` even if the operator pasted it in Advanced JSON, or block publish with a clear line: “Layout is not part of the flow — remove `cx`.” Prefer strip on wire + keep positions locally.
- **Do** keep auto-layout for first visit / missing ids.
- **Do not** put positions in `conversation_policy` or any other published field.
- **Do not** change node/edge JSON.

---

## Exit criteria

1. `docForWire()` JSON has no `cx` key (or it is omitted/null).
2. Publish of the live inbound draft no longer returns `cx` / `policy_validation_failed`.
3. Dragging a node, reload, positions restore **in this browser**.
4. Relayout does not reintroduce `cx` on the next save.
5. README / builder help no longer claim Go ignores `cx`.

---

## Verify

- Open `/CC/admin/flows/coral-telecom-inbound/builder`.
- Move two nodes → Save draft → GET draft → confirm no `cx`.
- Publish (if the rest of the graph is already valid) → 200 and new version.
- Hard refresh → nodes stay where you put them.
- Incognito → auto-layout, no crash.

## Risks

| Risk | Mitigation |
|---|---|
| Operator relied on `cx` in git-exported JSON | Migrate on load; document local-only layout |
| Advanced JSON still includes `cx` | Strip on wire |
| localStorage quota / private mode | Fall back to auto-layout; do not fail save |
