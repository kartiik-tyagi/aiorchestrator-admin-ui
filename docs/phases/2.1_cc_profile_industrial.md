## Goal

The Profiles form edits every field the kernel already stores on the three live profiles, uses **draft** APIs, and shows **server** validate next to the client preview.

## In scope

### Load / save / publish

- Load **draft first** (`GET /v1/profiles/{id}/draft`). If 404, fall back to `GET …/versions/latest`. If both 404, `emptyDoc`.
- Save draft: `PUT /v1/profiles/{id}/draft` (body = full document).
- Check: `POST /v1/profiles/{id}/validate` — merge server issues into the same list (mark source: local vs server).
- Publish: existing `POST …/versions`.
- Version history: `GET …/versions` as a **read-only** list (version, time). Opening a version is inspect-only unless the operator copies it into draft (confirm).
- Create: include `product: "call_center"` and `intent_catalog: []`. Do not start from a silent legacy empty product if we can set it.

### Form sections (add below existing, this order)

1. **Product** — closed `call_center`. Empty allowed (legacy). Wrong value = error (`product_mismatch`).
2. **Intent catalog** — table rows: `id`, `scope`, `action`, `department`, `product`, `examples[]`, `description`.
   - Scopes: `global` | `hub` | `in_room`
   - Actions: `navigate` | `answer` | `go_department` | `switch_language` | `request_agent` | `menu` | `done`
   - Prefer catalog keys if the server ever adds them; else constants matching `internal/profile/intent_catalog.go`.
   - `go_department` requires `department`.
   - Id pattern `^[a-z0-9][a-z0-9_]{0,63}$`. Unique ids.
   - Reject dial-like numbers in department / product / description / examples (same idea as Go `dialLike`).
3. **Conversation policy** — grouped, not a raw blob:
   - Interruption: `mode`, `welcome_mode` (`off`|`on`|`after_ms` — **no inherit** at profile level), `welcome_grace_ms` (only when after_ms), `min_barge_chars`, `min_barge_ms`, `partial_confidence`, `cooldown_ms`
   - Listen: `no_input_timeout_ms`, `retry_budget`, `feed_during_speak` (default visual off; warn “debug / soak only”)
   - Utterance endpointing: `enabled`, `end_silence_ms`, `min_speech_ms`, `max_hold_ms`, `barge_silence_ms`
   - `incomplete_prefixes` chip list
   - Failure: `safe_retry_max` 0–3, optional fallback scenario names from the fallback catalog
   - Recording: `enabled`, `consent_prompt_ref`, `retention_class`
   - Channel: `allowed_clocks` from catalog `clocks`, `allowed_capabilities`
   - Mandatory delivery: `enabled`
4. **Audio levels** — `inbound_normalize`, `inbound_target_rms` (0–0.5], `inbound_max_gain` [1–16], `inbound_noise_floor_rms` [0–0.1], `tts_limiter`, `tts_peak_limit` (0–1]
5. **Persona TTS** — `persona.tts.pace` (>0), `persona.tts.temperature` (finite)

### Preserve rule

`patch` / `patchIn` only. Never replace the loaded document with `emptyDoc()` except on create or true 404. Advanced JSON stays as last resort.

### Client validator

Extend `profileValidate.js` with product, catalog, policy ranges, audio ranges, TTS — same messages as Go where possible.

## Do / Do-not

- **Do** GET `coral-telecom-limited` and show 17 intents without the operator opening JSON.
- **Do** no-op draft save and confirm `intent_catalog` length unchanged.
- **Do not** send a document built only from form defaults.

---

## Exit criteria

1. All three live profiles open with catalog, policy, levels, and TTS (if set) equal to GET.
2. Changing only display name → draft save → GET draft: `intent_catalog` identical.
3. Invalid pace / RMS / intent id is caught locally **and** server validate surfaces if the operator publishes.
4. Draft-only changes are visible after reload (not only after publish).
5. Version list shows existing versions for a live profile.

## Verify

- Edit display name, Save draft, reload, revert.
- Set `persona.tts.pace` to `0` → local error; fix to `1.15`.
- `POST /v1/profiles/{id}/validate` with the on-screen doc returns 200 for a known-good live doc.

| Risk | Mitigation |

| Catalog dropdowns not in `/v1/meta/catalog` | Constants + comment pointing at Go |
