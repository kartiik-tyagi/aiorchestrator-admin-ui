# Phase 5.5 — MI profile: terminology glossary + home badges

**Wave:** MI memory + insights  
**Depends:** 5.4  
**Unlocks:** 5.6  
**Lock:** [PROGRAMME.md](./PROGRAMME.md), [WAVE_5_GAP.md](./WAVE_5_GAP.md)

---

## Operator outcome

I can maintain the speech-correction glossary (canonical terms + aliases) for a desk, and I can see at a glance whether memory suggestions or insights are waiting — without confusing terminology with the people/products directory.

---

## Goal

Terminology management UI (MI.17 APIs) plus light home/profile signals. Pending alias **decisions** stay primarily in the Memory inbox (5.3); this phase is the confirmed glossary and add path.

---

## In scope

### Terminology on `/MI/admin/profiles/:id`

- List: `GET /mi/v1/terminology?profile_id=…` (exact query per live handler).  
- Add: canonical term, kind, aliases → `POST /mi/v1/terminology`.  
- Copy: “Speech correction for STT → MoM. Raw transcript rows are never rewritten. Pending alias suggestions also appear in Memory inbox.”  
- Optional: confirm/reject via terminology alias routes **or** deep-link “Open inbox” — do not build two competing queues with different rules.

### Home `/MI/admin`

- Optional badges: pending inbox count (sum across profiles **or** “open a profile”) — keep cheap: only if one profile filter or skip cross-profile fan-out. Prefer profile-level badge only if home fan-out is expensive.  
- Short trust legend: MoM / Summary / Feedback one-liners linking Wave 5 gap doc concepts.

### Meeting list polish

- Optional column or icon when `insights.stale` if list payload includes it; otherwise skip (meeting GET only).

## Out of scope

- Terminology Learning Lab synthetic runner (`/mi/v1/lab/*`) as operator UI.  
- Embeddings / PDF.  
- Auto-confirm.

---
