# Phase 3.3 — MI: meetings + Case B + transcript

**Wave:** MI  
**Depends:** 3.2  
**Unlocks:** 3.4–3.5  
**Lock:** [PROGRAMME.md](./PROGRAMME.md)

---

## Operator outcome

I can run the lab path: create a meeting on a profile → push an attributed transcript → see the words. I am never offered End on a meeting that cannot end.

---

## Goal

Meeting list, create, lifecycle actions that match **valid state**, Case B ingest, and a transcript pane. Poll for job/facet updates. No approve or Ask yet.

---

## In scope

### Routes

- `/MI/admin/meetings` — list (`?profile_id=` filter)
- `/MI/admin/meetings/:id` — workspace (this phase: header + lifecycle + Case B + transcript; later phases add panes)

### Create

`POST /mi/v1/meetings` with `profile_id`, `external_meeting_id`, `participant_namespace`, optional `title`.  
Explain: this **snapshots** the profile.

### List

`GET /mi/v1/meetings?profile_id=` — columns: title, profile, lifecycle, job state, draft/official chips.

### Detail header (facet bundle)

Show: `id`, `profile_id`, `external_meeting_id`, `title`, `lifecycle`, `partial_capture`, authoritative generation, job `{id,state,error_code}`, draft `{ready}`, official `{official_version}`.

**Poll** `GET /mi/v1/meetings/{id}` every 3–5s while the page is open and job is not terminal. SSE (`…/events`) is **not** required (doc 08: poll is enough for V1).

### Lifecycle buttons (offer only if legal; still handle `invalid_lifecycle`)

| Action | API |
|---|---|
| Start capture | `POST …/start-capture` |
| End | `POST …/end` |
| Cancel | `POST …/cancel` |
| Regenerate | `POST …/regenerate` |

Hide or disable illegal buttons from the last GET lifecycle. Confirm Cancel.

### Case B

- Textarea for attributed transcript JSON (operator pastes a fixture).
- Auto-generate `Idempotency-Key` (shown, copyable); new key on each distinct push unless the operator reuses it to test dedupe.
- Optional `X-MI-Ingest-Token` field only if the lab uses one (localStorage, not logged).
- `POST …/transcripts` — show `accepted`, `generation`, `decision` (`accepted_supersede` | `deduped_noop` | `rejected` | `stored_candidate`), `job_id`.
- Rejected: show server message (`b_rejected_quality`, `insufficient_transcript`, …).

### Transcript pane

- `GET …/transcript` (optional `?generation=`)
- Ordered segments: seq, speaker/display name, text
- Generation picker if the facet lists generations

## Out of scope

- Ask (3.5)

## Do / Do-not

- **Do** poll; do not block the UI waiting for MoM LLM (doc 08: never wait on HTTP for full MoM).
- **Do not** enable Case B on a sealed generation without showing supersede risk.
- **Do not** offer Start capture as the default path; Case B is the V1 operator path.

## Exit criteria

1. Create meeting on `ui-mi-demo` (or any profile) → appears in list.
2. Case B fixture stores; transcript pane shows segments.
3. Dedupe with the same Idempotency-Key shows `deduped_noop`.
4. Cancel / end follow lifecycle; illegal actions are not offered.
5. Job state updates without a full page reload.

---

## Verify

- Push a minimal attributed fixture twice with the same key → second is deduped.
- End meeting; regenerate if the UI offers it after a sealed gen.
- Stop polling on unmount (no leaked intervals).
