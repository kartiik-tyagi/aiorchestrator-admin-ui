## Operator outcome

I can switch tabs, check the transcript, refresh, or share a link to the MoM tab without losing unsaved edits, and the page warns me before anything would throw them away.

---

## Goal

Owner decision OD-DOC-1 puts editing inside the meeting page's MoM tab. Four defects in `MeetingDetail.jsx` make that unsafe today. Fix them before any editing UI ships.

---

## In scope

### 1. Draft state lives on the page, not in the tab

- New hook `src/lib/useDraftWorkspace.js`, called once in `MeetingDetail`:  
  `{ draft, working, dirty, loadedVersion, canUndo, canRedo, edit(fn), undo(), redo(), save(), reload(), conflict, resolveConflict(choice) }`.  
- `save()` sends **only changed top-level fields** (`mom` / `decisions` / `actions`) plus `expected_version: loadedVersion`.  
- `409 draft_version_conflict` → `conflict = { mine: working, theirs: body.current }`. `resolveConflict('mine')` re-saves with the new version; `'theirs'` replaces working.  
- `409 job_in_progress` → keep edits, show "A regeneration is running; save after it finishes."  
- The MoM tab receives the hook's state as props. Unmounting the tab loses nothing.

### 2. Tab in the URL

- `useSearchParams`: `?tab=overview|transcript|mom|summary|feedback|approve|official|ask`, plus `&v=N` for the Official version (7.4) and `&seg=<segment_id>` for Transcript (7.3).  
- Default `overview`. Unknown value → `overview`.  
- Rename the `draft` tab key to `mom` (label unchanged).

### 3. Polling pauses while dirty

- The 4 s facet poll skips its tick while `dirty`. It resumes after save or discard.

### 4. Leave guard

- `setDirtyGuard(dirty, 'minutes')` from the hook (existing `lib/dirtyGuard.js`).  
- `beforeunload` listener while dirty.  
- The app uses `BrowserRouter`, so `useBlocker` is unavailable. Guard the in-app exits explicitly: "← Meetings" link and the MI sidebar `NavLink`s call `confirmLeaveDirty()` in `onClick` and `preventDefault()` on cancel.

### 5. Regenerate guard (Overview)

- `mi.regenerate(id)` → `409 draft_has_edits` → `Modal`: "This draft has edits saved since it was generated. Regenerating replaces them. A copy is kept in history." Buttons: **Regenerate anyway** (`discard_edits=1`) / **Cancel**.  
- If the page itself is dirty, Regenerate is disabled with the reason.

## Backend contract

- `PATCH …/draft` with `expected_version`; `409 draft_version_conflict { current }`, `409 job_in_progress` (MI.37)  
- `POST …/regenerate[?discard_edits=1]`; `409 draft_has_edits` (MI.37)

## Current baseline

- `const [tab, setTab] = useState('overview')`; tabs render with `{tab === 'draft' && <DraftEditor/>}`.  
- `DraftEditor` holds its own state and does a GET-then-PATCH version check.  
- `dirtyGuard` is only consulted by the product switcher.  
- Regenerate has no confirmation.

## Do / Do-not

| Do | Do-not |
|---|---|
| Send only changed fields with `expected_version` | Send all three fields on every save |
| Keep edits across tab switches | Keep edit state inside a tab component |
| Confirm before regenerate over edits | Call `discard_edits=1` without the modal |

- [ ] Edit (via a temporary test hook or 7.3 stub) → switch to Transcript → back: edits intact

- [ ] "← Meetings", sidebar links and closing the tab all warn while dirty  
- [ ] Regenerate on edited draft shows the modal; confirm sends `discard_edits=1`
