# Phase 0.1 — Product home + `/CC/admin` + `/MI/admin` shells

**Wave:** Shared foundation  
**Depends:** none  
**Unlocks:** 1.1 (CC) and 3.1 (MI)  
**Lock:** [PROGRAMME.md](./PROGRAMME.md)

---

## Operator outcome

Opening the app, I choose **Call Center** or **Meeting Intelligence**. I never land in a mixed nav. Old bookmarks still work.

---

## Goal

Split the single-shell app into a product picker plus two product shells, without changing any CC field editors or adding MI screens yet.

---

## In scope

- Route map below (exact paths).
- Product picker at `/` — two large cards, operator language (“Answer phone calls” / “Minutes and Ask on meetings”).
- `CcShell` — today’s sidebar, topbar, catalog provider, CC pages. Nav `to` values moved under `/CC/admin`.
- `MiShell` — own sidebar, own topbar (token only; no tenant-engine status as if it were CC). Placeholder home copy: “Meeting Intelligence admin — screens land in later phases.” No fake MI CRUD.
- Redirects from every **old** CC URL into the new CC path (replace, so history stays tidy).
- `/CC` → `/CC/admin`, `/MI` → `/MI/admin`.
- Vite proxy: add `/mi/v1` (HTTP). Keep `/v1` and `/edge`. WebSocket for MI media is **not** required this phase.
- Split API folders **without breaking imports yet**: keep `src/api/client.js` working; add empty-or-stub `src/api/mi/client.js` with a comment that 3.1 fills it. Prefer moving CC client to `src/api/cc/client.js` and re-exporting from the old path so existing pages compile.
- Product switcher in both shells (small, always visible): “Call Center | Meeting Intelligence”.
- `SETUP_STEPS` and `readinessChecklist` `to` fields updated to `/CC/admin/...`.
- Internal `Link`/`NavLink` targets in Dashboard, Pins, Tutorial, fieldGuide (if it hard-codes paths).

## Out of scope

- Any new CC or MI form fields.
- Builder / validator / bindings changes.
- CatalogProvider on the MI shell (MI does not use `/v1/meta/catalog`).
- Redesign of CSS variables (reuse existing).

## Do / Do-not

- **Do** keep every existing CC page working after redirect.
- **Do** use `Navigate replace` for legacy URLs.
- **Do not** wrap MI in `CatalogProvider` (it would hammer `/v1` for no reason; CC shell keeps it).
- **Do not** add MI CRUD placeholders that 404.

---

## Exit criteria

1. `/` shows exactly two product cards.
2. `/CC/admin` shows today’s dashboard and CC-only nav.
3. `/MI/admin` shows MI-only chrome and a non-broken placeholder (no CC screens).
4. Every legacy CC URL listed above lands on the equivalent `/CC/admin/…` page.
5. `SETUP_STEPS` / dashboard setup strip links do not 404.
6. Vite `/mi/v1` proxy is present (`ORCH_URL` still overrides the target).
7. No CC page imports MI types; no MI file imports flow/profile validators.

---

## Verify

- Browser: `/` → click CC → dashboard. Click MI → placeholder. Use product switcher both ways.
- Type `/engines` → end on `/CC/admin/engines`.
- Type `/CC/admin/flows/<live-id>/builder` — canvas still loads (layout still writes `cx` until 1.1 — that is OK).
- `curl http://localhost:5183/v1/health` still returns orch health.
- Optional: `curl http://localhost:5183/mi/v1/health` (proxy only).

## Risks

| Risk | Mitigation |
|---|---|
| Missed hard-coded `/engines` link | Grep `to: '/` and `href="/` before done |
| CatalogProvider on root causes MI to show CC errors | Provider lives only inside `CcShell` |
| Vite 8 IPv6 | Docs still say `localhost:5183` not `127.0.0.1` |
