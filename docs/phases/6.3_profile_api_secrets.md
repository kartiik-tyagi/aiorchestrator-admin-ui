# Phase 6.3 — Profile API secrets (masked) + publish gate

**Wave:** External API Tool + Typed Listen  
**Depends:** 6.2  
**Unlocks:** 6.4 publish path  
**Lock:** [WAVE_6_API_TOOL_GAP.md](./WAVE_6_API_TOOL_GAP.md) G2

---

## Operator outcome

For each integration with `auth_type ≠ none`, I can set a secret (bearer / api_key / basic / headers), see only masked preview, and the UI warns before publish if a required secret is missing.

---

## In scope

- Per-integration secret panel using 6.1 client methods
- PUT `{ auth_payload }` shaped by auth_type (bearer_token | api_key | username+password | headers map)
- Show `auth_set` + `auth_preview` only; never echo raw secret after save
- Publish CTA: soft-block / clear error when auth needed and `auth_set` false
- Never write secrets into draft JSON or localStorage

## Out of scope

- Flow builder changes
- Snapshot internals (server on publish)

## Exit criteria

- [ ] List/get/put/delete secrets from Profiles UI  
- [ ] Publish gate surfaces missing secret in words  
- [ ] Lint clean; no secret in profile draft payload
