# Phase 3.4 — MI: draft / approve / official / export

**Wave:** MI  
**Depends:** 3.3  
**Unlocks:** 3.5 (Ask prefers official)  
**Lock:** [PROGRAMME.md](./PROGRAMME.md)

---

## Operator outcome

I can correct the minutes and lock an official version I trust. Approve is never a surprise when AI-unsupported fields remain.

---

## Goal

Draft view/edit, two-step approve with reconciliation, official + history, export. Trust gate matches DR-2: reject approve if any structured field is still `unsupported_ai`.

---

## In scope

Add panes to `/MI/admin/meetings/:id`:

### Draft

- `GET /mi/v1/meetings/{id}/draft`
- Editable fields from the payload (do not invent section ids — render what the draft has; MoM sections follow profile template when present).
- `PATCH` with the changed fields; show new `version`.
- Version conflict (`draft_version_conflict`): tell the operator to reload; do not overwrite silently.
- Highlight fields flagged `unsupported_ai` (or equivalent in the payload) **before** they click Approve.

### Approve (two steps)

1. `POST …/approve` with optional `approver_label` → reconciliation **preview**.
2. Operator reviews `reconciliation_ops[]` (show each op in words).
3. `POST …/approve/confirm` with `draft_id`, `draft_version`, `reconciliation_ops[]`.

If preview returns `unsupported_ai_present`, **do not** enable Confirm. List the fields.

### Official

- `GET …/official` — read-only current official.
- `GET …/official/history` — prior versions.
- Copy: “Official is immutable. Ask prefers official over draft.”

### Export

- `GET …/export` — offer `json` and `markdown` if the API accepts a query; otherwise download whatever it returns. Link + filename from `Content-Disposition` if present.

## Out of scope

- Ask (3.5).
- Changing pipeline jobs.
- Editing official in place (forbidden).

## Exit criteria

1. Edit draft → version bumps on GET.
2. Approve is blocked while `unsupported_ai` remains, with the field named.
3. After confirm, official GET matches the approved draft; history has a prior row if one existed.
4. Export downloads.
5. Two-tab edit: second confirm or patch shows version conflict in words.
