# Phase 5.3 — MI profile: memory inbox + insights flags

**Wave:** MI memory + insights  
**Depends:** 5.2  
**Unlocks:** 5.4  
**Lock:** [PROGRAMME.md](./PROGRAMME.md), [WAVE_5_GAP.md](./WAVE_5_GAP.md)

---

## Operator outcome

I can confirm or reject pending identity / terminology suggestions for the desk. I can turn Meeting Summary and AI Feedback **on or off** for future insights jobs — both default off.

---

## Goal

Profile-level memory inbox (OD-MEM-1/2) and structured `rules.insights.*` toggles (OD-MEM-7), without mixing advice into MoM.

---

## In scope

### Memory inbox — `/MI/admin/profiles/:id`

- `GET …/memory/inbox` → table: kind, alias, target (entity / canonical), status, created.  
- Actions: **Confirm** / **Reject** per row (`item_id` as returned).  
- Optional `actor_label` field.  
- Send `X-MI-KB-Token` when set (5.2).  
- Empty state: “No pending suggestions.”  
- 401 → “KB token required or invalid.”  
- Badge/count on profile nav or section header.

### Insights flags (profile rules)

Structured toggles (patch full profile load→save):

| Flag | Default | Meaning |
|---|---|---|
| `rules.insights.summary` | off | Generate Meeting Summary after MoM succeeds |
| `rules.insights.feedback` | off | Generate AI Feedback after MoM succeeds |

Keep **Advanced JSON** for the rest of `rules` (case_b, kb, …) so unknown keys survive.

### Memory policy (optional structured)

If easy: number fields for known keys only — `summary_max_chars`, `feedback_max_items`, `inbox_max_pending`, `restatement_threshold` — else leave JSON editor from 3.2. Do not invent keys.

### Copy

- “Confirm applies org memory. It does not rewrite past Official minutes.”  
- “Summary and Feedback stay off until you enable them. They never become Official by themselves.”  

## Out of scope

- Meeting panes (5.4).  
- Auto-confirm.  
- Advice at approve.  
- Editing Feedback into draft from profile page.
