## In scope

### Client methods (add only what the binary has)

| Method | Path | Notes |
|---|---|---|
| `listMemoryInbox` | `GET /mi/v1/profiles/{id}/memory/inbox` | optional `?limit=` |
| `confirmInboxItem` | `POST …/memory/inbox/{item_id}/confirm` | body `{ actor_label? }`; header `X-MI-KB-Token` when set |
| `rejectInboxItem` | `POST …/memory/inbox/{item_id}/reject` | same |
| `importPeopleCsv` / `exportPeopleCsv` | `POST/GET …/kb/people/import\|export` | multipart or body per live handler — **inspect lab/tests, do not guess** |
| `importProductsCsv` / `exportProductsCsv` | people twin | same |
| `enableKg` | `POST …/kg/enable` | live rules.kb |
| `deleteKbDoc` | `DELETE …/kb/{doc_id}` | if 3.2 omitted it |
| `listEntities` / `getEntity` | `GET /mi/v1/kb/entities` | `profile_id`, `entity_type` query |
| `refreshInsights` | `POST /mi/v1/meetings/{id}/insights/refresh` | 400 `insights_disabled`, 404 no draft |
| `listTerminology` / `createTerminology` | `GET/POST /mi/v1/terminology` | profile-scoped list query as live |
| `confirmTermAlias` / `rejectTermAlias` | `POST /mi/v1/terminology/aliases/{id}/confirm\|reject` | optional if inbox covers writes — still wrap for 5.5 |

Shared helper: attach `X-MI-KB-Token` from a module-level setter or per-call `hdrs` (mirror ingest-token pattern). **Do not** send CC `Authorization` on MI calls.

### Types (`src/api/mi/types.js`)

JSDoc for:

- `MemoryInboxItem` (`item_id`, `kind` = `kb_alias|term_alias`, alias fields, status, targets)
- Meeting facet `insights` (`status`, `stale`, `source_draft_version`, `draft_version`, `meeting_summary`, `ai_feedback`, `error_code`)
- Feedback payload shape `{ items[], abstained?, reason? }` — match live JSON, do not invent kinds

Update the header comment in `client.js` with date + which routes returned 200 vs 404 on this binary. Hide UI later phases must not invent 404 routes.
