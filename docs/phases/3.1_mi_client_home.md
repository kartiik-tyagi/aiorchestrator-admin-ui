# Phase 3.1 — MI: client + home

**Wave:** MI  
**Depends:** 0.1  
**Unlocks:** 3.2–3.5  
**Lock:** [PROGRAMME.md](./PROGRAMME.md)

---

## Operator outcome

I open Meeting Intelligence and know the module is alive — or I see “MI API not reachable” in words, not a blank page.

---

## Goal

A real MI API client and a dashboard that only binds **implemented** `/mi/v1` routes. No fake screens.

---

## In scope

### Vite

- Confirm `/mi/v1` proxy from 0.1. Same `ORCH_URL` target as `/v1`.

### Client `src/api/mi/client.js`

Wrap routes that **exist on this binary** (`internal/mi/facade/facade.go`):

| Method | Path |
|---|---|
| GET | `/mi/v1/health` |
| POST/GET | `/mi/v1/profiles` |
| GET/PUT | `/mi/v1/profiles/{id}` |
| PUT | `/mi/v1/profiles/{id}/kb/{doc_id}` |
| GET | `/mi/v1/profiles/{id}/kb` |
| POST | `/mi/v1/profiles/{id}/ask` |
| POST | `/mi/v1/profiles/{id}/ask/sessions` |
| POST/GET | `/mi/v1/meetings` |
| GET | `/mi/v1/meetings/{id}` |
| POST | `…/start-capture`, `…/end`, `…/cancel`, `…/transcripts`, `…/regenerate` |
| GET/PATCH | `…/draft` |
| POST | `…/approve`, `…/approve/confirm` |
| GET | `…/official`, `…/official/history`, `…/export`, `…/transcript` |
| POST | `…/ask`, `…/ask/sessions` |
| GET | `/mi/v1/ask/sessions/{id}` |
| POST | `/mi/v1/ask/sessions/{id}/turns` |
| POST | `/mi/v1/retention/purge` |

**Probe once (dev console or a tiny `mi/meta.js`):**

- `GET /mi/v1/meta` — locked in doc 08; **not** in facade.go. If 404, do not add a Meta screen.
- `GET /mi/v1/profiles/{id}/actions` — locked in doc 08; **not** in facade.go. Hide ledger until 3.5 probe says 200.

Same error type as CC (`ApiError` with code/message/details). No Bearer unless we later learn MI uses the CC token — V1 MI is open; do not send CC tenant as if it were MI.

### Home `/MI/admin`

- Health card (status + db if present).
- Counts: profile list length, meeting list length (empty is OK).
- Two actions: “New profile” (links 3.2 route even if 3.2 is a stub page), “New meeting”.
- Error copy table for common codes (extend in later phases): `profile_not_found`, `meeting_not_found`.

### Types

- `src/api/mi/types.js` — JSDoc for health, profile list item, meeting facet (from doc 08 §4). Do not copy CC `ProfileDocument`.

### Shell

- MI nav this phase: Home. Profiles / Meetings links may 404-as-placeholder until 3.2/3.3 — prefer a “Coming in next phase” panel rather than a broken list. **Better:** 3.1 ships Home only; nav items for Profiles/Meetings appear when those phases land. This phase: Home + disabled nav or “next”.
