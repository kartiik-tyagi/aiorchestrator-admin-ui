# Phase 7.1 — MI minutes: client download + shared document renderer

**Wave:** MI minutes (MoM document)  
**Depends:** orchestrator **MI.38** Closed  
**Unlocks:** 7.2  
**Lock:** [PROGRAMME.md](./PROGRAMME.md); orchestrator `docs/meeting-intelligence/16_MOM_DOCUMENT_AND_EXPORT.md` (§4 decisions, §5 document model)

---

## Operator outcome

When I open a meeting's minutes I see a readable document with sections, decisions and an action table, laid out like the PDF I will download. I no longer see a form or JSON.

---

## Goal

Build the pieces every later wave-7 phase uses: a client that downloads files (not JSON), a view model that mirrors the server's document model, and one `MinutesDocument` component. This phase is **read-only**; editing comes in 7.3.

---

## In scope

### Client `src/api/mi/client.js`

- `mi.downloadExport(id, { format, draft, officialVersion })`: `fetch` → on 2xx read `blob()`, take the file name from `Content-Disposition` (`filename*` first, then `filename`), save through an object URL and a temporary `<a download>`, then revoke the URL. On non-2xx parse the JSON error into `ApiError` like `request()` does.  
- `format` values: `json`, `md`, `pdf` (and `docx` after 7.6). Fix the existing `exportMeeting(…, { format: 'markdown' })` caller to `md`.  
- `mi.patchDraft(id, body)` passes `expected_version` through unchanged (MI.37).

### View model `src/lib/miDocument.js` (new, pure functions)

- `draftToDocument(facet, draft, speakers)` and `officialToDocument(facet, official, speakers)` → `{ kind, version, title, statusLine, watermark, meta, sections[], decisions[], actions[] }`, matching doc 16 §5 block for block.  
- Body text → bullet items (`- ` lines); non-bullet lines stay paragraphs.  
- Attendees = distinct `display_name` from the authoritative transcript, first-appearance order.  
- Owner shows `owner_display_name`, else `owner_user_id`, else —.

### Components `src/pages/mi/minutes/`

- `MinutesDocument.jsx`: the white "paper" page (OD-DOC-6): title block, status line, draft watermark, metadata grid, sections, numbered decisions, actions table, flags on `unsupported_ai` claims. Props: `doc`, `mode` (`preview` only in 7.1).  
- `OutlineRail.jsx`: sections + Decisions (count) + Actions (count, flag count); click scrolls; scroll-spy highlights.  
- `DownloadMenu.jsx`: PDF / Markdown / JSON; calls `downloadExport`; busy state; error toast via `miErrorSentence`.

### Styles `src/styles.css`

- A `.minutes-paper` scope with its own light tokens (paper, ink, rule, accent) so the page stays white in the dark console. Print-like width (A4 ratio at 100%), serif body, sans labels.

### Errors `src/lib/miErrors.js`

- Sentences for `unsupported_format`, `no_draft`, `no_official`, `official_version_not_found`.

## Backend contract (read-only)

- `GET /mi/v1/meetings/{id}` facet, `GET …/draft`, `GET …/official`, `GET …/official/history`, `GET …/transcript`  
- `GET …/export?format=json|md|pdf[&draft=1|&official_version=N]` → file with `Content-Disposition` (MI.38)

---

## Current baseline

- `DraftEditor.jsx` renders a form; `OfficialPane.jsx` renders section cards and downloads JSON via `JSON.stringify` in the browser.  
- `request()` always parses JSON or text; no blob path.  
- `exportMeeting` sends `format=markdown`, which the server rejects.

## Risks

- Browsers block `<a download>` on cross-origin URLs; the Vite proxy keeps `/mi/v1` same-origin, and object URLs avoid the issue anyway.  
- `Content-Disposition` parsing of `filename*` must decode percent-encoding (non-ASCII titles).
